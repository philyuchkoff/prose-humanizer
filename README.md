# human — редактор ИИ-текста

> Скилл-редактор для любого LLM-агента (opencode, Claude Code, Cursor, Codex, Windsurf и др.). Убирает «запах нейросети» из русского и английского текста, не трогая факты и голос автора.

## Что это

`human` — это не детектор ИИ и не «обфускатор». Это **инструкция для LLM**, которая превращает канцелярский машинный текст в такой, который человек прочитает без зевоты. Мерило — читатель, а не GPTZero.

Особенности, отличающие от других «хьюманайзеров»:

- **Двуязычный** — правила для русского и английского в одном скилле, авто-определение языка.
- **Не стерилизует** — голос автора, его примеры, ирония и вводные сохраняются; минимальная достаточная правка.
- **Не выдумывает факты** — жёсткий запрет на добавление данных, которых нет в исходнике; нет цифры — пометка `[нужны данные: что именно]`.
- **Учитывает жанр** — ТЗ, пост, инструкция, статья, письмо и договор редактируются по разным правилам.
- **Структурный подход** — каталог паттернов с уровнями `error` / `high` / `low` / `note` и иерархия лечения (удалить → заменить фактом → сказать проще).

## Когда активировать

Триггеры:

- «очеловечь», «причеши текст», «убери канцелярит», «звучит как нейросеть», «проверь на слоп», «сделай читаемым»
- «humanize», «de-AI», «remove AI smell», «make it sound human»
- приложенный текст после переписки с моделью + просьба отредактировать

## Установка

### opencode (рекомендовано)

Глобально для текущего пользователя:

```bash
cp -r /Users/user/git/humanizer/human ~/.config/opencode/skills/human
```

В проект (чтобы переносилось через git):

```bash
mkdir -p .opencode/skills
cp -r /Users/user/git/humanizer/human .opencode/skills/human
```

После копирования скилл доступен сразу — перезапуск opencode не требуется.

### Claude Code, Cursor, Codex, Windsurf и другие

Скилл кросс-агентный: достаточно положить `SKILL.md` и папку `references/` туда, где ваш агент ищет скиллы. Типичные пути:

| Агент | Путь |
|---|---|
| Claude Code | `~/.claude/skills/human/` |
| Cursor | `~/.cursor/skills/human/` |
| Codex | `~/.codex/skills/human/` |
| Windsurf | `~/.codeium/windsurf/skills/human/` |

Для глобальной установки сразу во все поддерживаемые агенты используйте [skills](https://github.com/vercel-labs/skills):

```bash
npx skills add /Users/user/git/humanizer/human --global
```

(Команда работает после публикации скилла в git-репозиторий; для локального пути используйте копирование, как показано выше.)

## Быстрый старт

После установки просто дайте агенту текст и попросите отредактировать:

> Причеши эту статью для Хабра, пожалуйста.
>
> <текст>

или

> Humanize this English text:
>
> <text>

Агент сам определит язык, жанр и режим (`careful` по умолчанию), проведёт аудит по каталогу паттернов, внесёт точечные правки и вернёт результат в формате:

1. Отредактированный текст
2. `---`
3. **Что изменено** — 3–7 пунктов
4. **На решение автора** — вкусовые предложения (в текст не внесены)
5. **Нужны данные** — где не хватило фактов (если есть)

## Режимы работы

| Режим | Что делает | Когда просить |
|---|---|---|
| `careful` (по умолчанию) | Точечные правки по находкам, структуру не меняет | «причеши», «убери слоп», «отредактируй» |
| `deep` | Можно перестраивать абзацы и порядок аргументов | «перепиши нормально», «глубокая переработка» |
| `audit` | Только таблица находок, текст не трогать | «проверь», «что не так», «найди слоп» |

## Жанры

Скилл автоматически выбирает жанр по тексту, но можно указать явно:

| Жанр | Применяется к | Что считать нормой |
|---|---|---|
| `doc` | инструкция, справка, документация | списки, шаги, формальный тон |
| `article` | статья, лонгрид, блог | подзаголовки, тире, длинные абзацы |
| `post` | пост в канал, сообщение в чат | эмодзи, жаргон, обрывочность |
| `letter` | письмо клиенту, коллеге | вежливые формулы, формальный регистр |
| `spec` | ТЗ, регламент | канцелярит — язык жанра |
| `legal` | договор, нормативный текст | ничего не править, лучше отказаться |
| `academic` | научный текст | «является», пассив, терминология |
| `fiction` | художественная проза | почти ничего; лучше отказаться |

## Структура скилла

```
human/
├── SKILL.md                  # главный файл: триггеры, 3 принципа, факт-замок, шаги
├── README.md                 # этот файл
└── references/
    ├── patterns.md           # ~50 паттернов с severity (error/high/low/note) и примерами
    ├── voice.md              # голос автора: как снять и применить паспорт
    ├── false-positives.md    # 25 пунктов: что НЕ трогать
    └── genre-rules.md        # жанры и режимы — как они меняют правила
```

## Пример

**До:**

> В современном мире автоматизация складского учёта играет ключевую роль в развитии любого бизнеса. Данная обработка представляет собой мощный инструмент, который позволяет осуществлять контроль остатков в режиме реального времени. Важно отметить, что внедрение не требует снятия конфигурации с поддержки. Нами было реализовано более 40 внедрений. Подводя итог, можно с уверенностью сказать, что обработка открывает новые горизонты для оптимизации складских процессов.
>
> Надеюсь, это поможет! Если у вас есть вопросы — дайте знать.

**После:**

> Обработка показывает остатки по складам на текущий момент — без пересчёта и без ожидания регламентного задания. Ставится расширением, типовую с поддержки снимать не нужно. Мы поставили её больше чем на 40 баз.
>
> [нужны данные: что именно «оптимизируется» — время на инвентаризацию? число пересортов?]

**Что изменено:** убран пустой зачин и пустой вывод; «представляет собой мощный инструмент» → что делает; «осуществлять контроль» → «показывает»; «важно отметить» удалено; пассив «нами было реализовано» → «мы поставили»; обёртка чат-бота удалена; цифра 40 сохранена; «новые горизонты» не заменены выдумкой — запрошены данные.

## Чего скилл не делает

- **Не заменяет длинное тире в русском** — это нормальная пунктуация, а не маркер ИИ (в отличие от английского).
- **Не вычищает вводные автора** — «по сути», «конечно», «существенно» у живого автора — это интонация, не мусор.
- **Не выдумывает данные** — нет цифры в исходнике → `[нужны данные]`, не правдоподобная фантазия.
- **Не редактирует художественную прозу и юридические тексты** — там другая логика и другие риски.
- **Не «стерилизует»** — голос, ирония, жаргон, смайлики, обрывочность в постах — всё остаётся.

## Происхождение

Скилл собран как объединение лучшего из двух open-source проектов:

- [thevseprod/humanizer-ru](https://github.com/thevseprod/humanizer-ru) (MIT) — двуязычный набор правил с двухпроходным процессом.
- [comol/Humanizer_RU](https://github.com/comol/Humanizer_RU) (MIT) — методология редактора: жанры, режимы, паспорт голоса, защита от стерилизации.

Убрана 1С-специфика и Python-линтер для универсальности; паспорт конкретного автора заменён инструкцией «как снять свой».
